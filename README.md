# 🎯 秋招管家（Recruit Manager）

> 秋招季的「投递 → 笔试/测评 → 进度」一条龙管理工具：连接 QQ 邮箱，自动把招聘邮件解析成日历事件；一张表管理所有投递记录；做完一场笔试测评，投递进度自动更新。

一个**完全本地运行**的 Windows/macOS 桌面应用。邮箱只读、数据不出本机、密钥只存本地文件。

---

## 📌 它解决什么问题

### 问题一：邮件太多，笔试/测评容易被遗忘

投递高峰期每天几十封邮件——笔试通知、在线测评、面试邀约混在一起，都在催、都有时限：

- 忘了某场**测评的截止时间**（很多是"收到邮件后 3 天内完成"）；
- 错过某场**固定时间笔试**（19:00 开考就是 19:00，错过即失去机会）；
- 昨天没做完的拖到今天，**自己根本记不清哪家到哪一步了**。

笔试测评一旦错过，往往意味着与这家公司无缘。靠人脑 + 记事本管几十条时间线，**本质上不可靠**。

### 问题二：手动维护投递进度，又烦又容易错

- 哪封邮件来了新通知全靠自己翻，**常常过好几天才补记**，进度长期与实际情况脱节；
- 每次做完笔试还要**回忆**"刚才做的是哪家"，再跑去表格改一行。

## ✨ 核心优势

### 1. 覆盖全类型招聘邮件，不只是"测评"

很多同类工具只认笔试/测评。本项目的解析器覆盖 **8 类**招聘邮件：

| 类型 | 说明 | 颜色 |
|---|---|---|
| `exam` | 固定时间笔试 | 🔴 红 |
| `assessment` | 限时测评 / 窗口笔试 | 🟠 琥珀 |
| `interview` | 面试邀约（含 AI 面试） | 🔵 蓝 |
| `resume` | 简历完善 / 信息补全提醒 | 🟢 绿 |
| `apply` | 网申投递确认 | 🟣 紫 |
| `offer` | offer / 意向书 | 🟢 青绿 |
| `campus` | 空中宣讲会 / 线下宣讲 | 🟠 橙 |
| `other` | 其他招聘相关 | ⚪ 灰 |

模型输出的别名会自动归一化（`ai面试`→`interview`、`网申`→`apply`、`宣讲`→`campus`），不会因措辞差异漏判。

> **实测**：88 封真实邮件深度重扫，识别出网申 5、测评 4、宣讲会 2、简历完善 2、AI 面试 1；快递广告等无关邮件正确过滤，0 批次失败。

### 2. 时间不做任何推算——没写就是没写

这是本项目的一条硬原则：**绝不编造时间**。

邮件正文里找不到日期时，`examAt` 和 `deadline` 一律留空，事件挂在**收信日**那一格并标注「**待定**」，点开可手动补填。市面上不少工具会自作主张"按收信日 +3 天"帮你推一个截止时间——那个数字是假的，害你错过真正的 DDL。

### 3. 针对推理模型做过适配，不会整批解析失败

`deepseek-flash` 这类**推理模型**会先输出一大段思维链，很容易把 token 配额吃光，导致 JSON 数组被截断在半路、整批邮件解析不出来。本项目做了三层防护：

- `maxTokens` 提升到 **20000**，单批 **5 封**（原 10 封）；
- JSON 被截断时**逐个抢救**已完整输出的对象，不整批丢弃；
- 某批彻底失败时，该批邮件的 key **不标记已读**，下次刷新自动重试。

### 4. 时区正确（已修复 UTC 慢 8 小时）

全流程以**本地时区**存储与显示。旧版本用 `toISOString()` 存 UTC、前端直接切字符串显示，导致北京时间**整整慢 8 小时**（晚上 18:32 显示成早上 10:32）。现已统一，并保留对历史 UTC 数据的兼容解析。

### 5. 一键启动 + 自动排障

`启动.bat` 内置三道保险：

1. 自动设置 `ELECTRON_MIRROR` 走 **npmmirror 国内镜像**，那 180MB 的 Electron 二进制不再卡在 GitHub 下载；
2. 装完**校验** `electron.exe` 是否真的存在，缺失就明确报错（不再静默失败、一个窗口都不弹）；
3. 启动后检测进程存活，**没起来就自动换软渲染重试**（`--disable-gpu --use-angle=swiftshader`）。

### 6. 深度重扫：升级规则后能补回历史邮件

识别规则升级后，旧邮件需要重新解析才能受益。顶栏「**深度重扫**」按钮（或命令行 `npm run deep-scan`）会用新规则重跑近期全部邮件，已存在的事件按 `key + type` 去重，不会重复入库。

### 7. 隐私优先

- 邮箱 **IMAP 只读**：只拉取，不发送、不修改、不删除任何邮件；
- 邮箱授权码、模型密钥只存本地 `config.json`，**代码不预置、不上传服务器**；
- 所有数据在本地 JSON 文件，零数据库、零后端；
- `config.json` 与 `data/` 均已在 `.gitignore` 中，**不会被误提交**。

### 8. 内置四个排障工具

| 命令 | 用途 |
|---|---|
| `npm run test-parse` | 识别能力自测：造 6 封典型邮件跑真实模型，输出命中率 |
| `npm run tls-diag` | TLS 诊断：同时测「严格校验」和「跳过校验」，一眼定位是不是代理在搞事 |
| `npm run deep-scan` | 命令行深度重扫历史邮件 |
| `npm run verify-ui` | 无头渲染验证：真实加载页面读 DOM，检查日历/横幅/时间渲染 |

## 🚀 部署过程

### 前置要求

| 依赖 | 版本 | 说明 |
|---|---|---|
| Node.js | ≥ 18 | [下载地址](https://nodejs.org/zh-cn/download)，应用运行依赖，装一次即可 |
| Git | 任意 | [下载地址](https://git-scm.com/)，仅克隆仓库用 |

Windows / macOS 均可（Electron 跨平台）。

### 第 1 步 · 克隆仓库

```bash
git clone https://github.com/king/recruit-manager.git
cd recruit-manager
```

### 第 2 步 · 启动（二选一）

**方式 A —— 双击启动（Windows 推荐）**

仓库自带 `启动.bat`，**直接双击**即可。首次运行会自动安装依赖（走国内镜像），装完自动弹出应用窗口，全程不用敲命令。

**方式 B —— 命令行启动**

```bash
# 中国用户建议先设置 Electron 国内镜像，否则 180MB 二进制容易下载失败
npm config set electron_mirror https://npmmirror.com/mirrors/electron/

npm install
npm start
```

> ⚠️ **Electron 装不上的典型症状**：双击 bat 后窗口一闪而过或完全无反应，且没有任何报错——几乎都是 Electron 二进制没下载成功。设好上面的镜像后重装即可。可用 `ls node_modules/electron/dist/electron.exe` 确认。

### 第 3 步 · 首次配置

点右上角**设置**，填入：

| 配置项 | 说明 |
|---|---|
| `user` | 你的 QQ 邮箱地址 |
| `auth` | **QQ 邮箱 IMAP 授权码**（16 位） |
| `llmBase` | 大模型接口地址（OpenAI 兼容格式） |
| `llmKey` | 大模型密钥 |
| `llmModel` | 模型名，默认 `deepseek-v4-flash` |

**QQ 邮箱授权码获取**：QQ 邮箱 → 设置 → 账号 → 开启 **IMAP/SMTP 服务** → 按提示拿到 16 位授权码。注意这是授权码，**不是 QQ 密码**。

配置保存在项目根目录 `config.json`（可用 `config.example.json` 复制改名）。该文件已被 `.gitignore` 排除，不会进版本库。

### 第 4 步 · 拉取邮件

点「**刷新邮件**」→ 招聘邮件自动变成日历事件。之后每次刷新走**增量拉取**，只取上次水位线之后的新邮件。

如果之前已经同步过、现在升级了识别规则，点「**深度重扫**」补回历史邮件。

## 🧩 工作原理

```
QQ邮箱 (IMAP, 只读)
   │  增量拉取（UID 水位线去重）
   ▼
邮件清洗 ──▶ 分批（5封/批）──▶ 大模型解析
                                  │  结构化事件：类型/公司/时段/截止/链接
                                  ▼
                        本地 JSON 存储 (data/store.json)
                                  │
             ┌────────────────────┴────────────────────┐
             ▼                                         ▼
     日历视图（横幅/今天要处理/月历/详情）      投递记录视图（表格/字段/图片）
             │
             ▼
   「完成并移除」笔试/测评 ──▶ 自动更新对应投递进度
```

```
recruit-manager/

```

## 🔧 常见问题

**Q：报错 `self signed certificate in certificate chain`？**

网络出口有中间人代理（公司网关、本地代理）替换了证书链，Node 不认。在 `config.json` 里加一行：

```json
"tlsInsecure": true
```

重启应用即可。也可用环境变量 `RM_TLS_INSECURE=1`。不确定是不是这个问题时，跑 `npm run tls-diag`，它会同时测严格和跳过两种模式并对比结果。

> 注意：这会关闭证书校验。仅在受信任的本地网络使用，换到可信网络时改回 `false`。

**Q：时间显示差 8 小时？**

已在本版本修复（统一本地时区）。若你用的是旧版，升级即可；历史 UTC 数据会自动兼容解析。

**Q：很多邮件识别不出来？**

按顺序排查：

1. 跑 `npm run test-parse` —— 自测 6 封典型邮件，看命中率；
2. 若模型是**推理模型**（如 `deepseek-flash`），确认 `maxTokens` 够大（本项目已设 20000）；
3. 点「深度重扫」用新规则重跑历史邮件。

**Q：邮件里没写时间怎么办？**

事件会挂在收信日显示「**待定**」，不会消失也不会被塞假时间。点开详情手动补填即可。

**Q：Electron 报 `GPU process isn't usable. Goodbye.`？**

无 GPU 的远程/虚拟环境常见问题。启动脚本已内置软渲染兜底；手动启动时加参数：

```bash
electron . --disable-gpu --disable-gpu-compositing --use-angle=swiftshader
```
